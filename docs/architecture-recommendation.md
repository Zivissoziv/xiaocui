# 技术架构建议

## 推荐结论

一期建议采用“Vue + Spring Boot 单体应用 + Spring AI + MyBatis + MySQL”的轻量架构。

先不引入异步任务、队列、对象存储和微服务。Excel 上传后由后端同步解析和分析，前端等待结果并展示 AI 生成的催办任务草稿。等后续遇到大文件、长耗时、多人并发或自动 WPS 定时同步，再考虑补异步任务和文件存储。

## 架构图

```text
浏览器 Vue + Element Plus
  |
  | 上传 Excel / 输入催办要求 / 确认发送
  v
Spring Boot 后端
  |
  +-- Excel 解析模块 Apache POI / EasyExcel
  |
  +-- 表格画像与裁剪模块
  |
  +-- Spring AI 模型适配层
  |
  +-- 催办任务生成与刷新模块
  |
  +-- 联系人匹配模块
  |
  +-- 消息发送适配器
  |
  v
MySQL
```

## 推荐技术栈

### 前端

- Vue 3
- TypeScript
- Element Plus
- Pinia
- Vue Router
- Axios

前端重点页面都是后台工具形态：上传、表格预览、AI 识别确认、催办任务列表、发送记录。Element Plus 的表格、表单、弹窗、抽屉、标签、步骤条足够支撑一期。

### 后端

- Java 17 或 Java 21
- Spring Boot 3
- Spring AI
- MyBatis 或 MyBatis-Plus
- MySQL 8
- Apache POI 或 EasyExcel

后端负责确定性部分：Excel 读取、Sheet 解析、列画像、上下文裁剪、缺项行筛选、联系人匹配、状态刷新和留痕。AI 只做字段语义判断、缺项摘要和催办文案生成。

### Excel 解析

优先建议：

- EasyExcel：适合读取较大 Excel，内存压力相对小。
- Apache POI：适合需要更细粒度处理 Sheet、单元格样式、公式和值类型时使用。

一期可以先用 EasyExcel 读取表格数据，如果遇到复杂格式再局部引入 POI。

### AI 层

使用 Spring AI 封装模型调用，建议在业务代码外再包一层 `AiAnalysisService`：

- 管理 prompt 模板。
- 强制 JSON 输出。
- 控制输入字段和 token 预算。
- 记录模型名称、prompt 版本、输入摘要、输出结果和错误。
- 方便后续切换内网模型、私有化模型或 OpenAI 兼容接口。

### 数据库

MySQL 存结构化业务结果：

- 分析会话。
- Excel 上传版本。
- Sheet 摘要。
- AI 分析结果。
- 联系人匹配结果。
- 待补充事项。
- 催办任务。
- 发送记录。

Excel 原文件一期可以先存本机目录，并在 MySQL 记录文件路径、哈希和上传时间。若公司规范不允许本机落盘，也可以只保存解析后的结构化数据，不保留原文件。

### 消息发送

一期建议先做接口适配层：

- `ManualCopySender`：生成待发送文案，人工复制发送。
- `EmailSender`：对接内网邮件。
- `InternalMessageSender`：后续对接企业内部消息中心。

发送渠道暂不确定时，先做 `ManualCopySender`，能最快验证 AI 提取和文案生成是否有价值。

## 后端模块划分

### session

管理一次催办会话：

- 创建会话。
- 保存用户催办要求。
- 记录截止时间。
- 查看会话状态。

### workbook

负责 Excel 上传和解析：

- 保存上传文件。
- 读取 Workbook。
- 遍历多个 Sheet。
- 识别表头。
- 生成列画像和 Sheet 摘要。

### table-profile

负责上下文压缩：

- 统计非空率。
- 猜测列类型。
- 抽取少量样例。
- 识别明显无关列。
- 生成传给 AI 的结构摘要。

### ai-analysis

负责 Spring AI 调用：

- 选择相关 Sheet 和字段。
- 识别负责人列和采集列。
- 生成缺项摘要。
- 生成催办文案。
- 校验 AI 返回 JSON。

### followup

负责催办业务：

- 生成待补充事项。
- 合并同一负责人的多行缺项。
- 生成催办任务。
- 刷新状态。
- 关闭已补充任务。

### contact

负责联系人匹配：

- 根据姓名、工号、邮箱、手机号、部门匹配内部员工。
- 处理同名候选。
- 标记需人工确认。

### sender

负责消息发送：

- 生成待发送内容。
- 调用渠道接口。
- 保存发送结果。

## 同步执行策略

一期先同步执行，流程简单：

```text
POST /api/sessions/{id}/analyze
  -> 读取 Excel
  -> 生成列画像
  -> 调用 AI 选择相关列
  -> 程序筛选缺项行
  -> 调用 AI 生成催办任务
  -> 入库
  -> 返回分析结果
```

为了避免请求过长：

- 限制单次上传文件大小。
- 限制最大 Sheet 数和最大行数。
- 超过阈值时提示用户先筛选 Sheet 或缩小范围。
- 后端设置接口超时时间，例如 60 到 120 秒。
- 记录分析状态，失败后允许重新分析。

## MVP 部署形态

```text
Nginx
  |
  +-- Vue 静态资源
  |
  +-- Spring Boot 应用
        |
        +-- MySQL
        +-- 本机上传目录
        +-- 内网模型 API
        +-- 内部消息渠道
```

## 关键工程原则

- 不把整个 Excel 全量传给 AI。
- 后端先做表格画像、列裁剪和缺项筛选。
- AI 输出必须符合 JSON Schema。
- AI 生成任务必须人工确认后发送。
- 一个催办会话绑定一个 Excel，但 Excel 可以反复上传新版本。
- 一个 Excel 可以包含多个 Sheet，默认分析所有可见 Sheet，允许用户排除。
- 每个催办任务保留来源 Sheet、行号和缺失字段。
- 联系人匹配不确定时不发送。
- 一期不做升级策略、主管抄送、异步队列和对象存储。

## 后续演进触发条件

满足以下情况再考虑引入异步任务、队列或对象存储：

- Excel 文件解析经常超过 120 秒。
- 单文件超过约 20MB 或 5 万行。
- 多人同时分析导致请求阻塞。
- 需要 WPS API 定时自动拉取。
- 需要长期保留大量原始 Excel 文件。
- 消息发送需要重试、定时发送或批量调度。
