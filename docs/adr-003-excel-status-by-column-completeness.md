# ADR-003: 通过负责人列和采集列完整性判定提交状态

## 状态

建议采纳

## 背景

一期表单主要通过 Excel 填写，后续通过内网 WPS API 下载表格。现有业务判断“谁已提交”的依据不是独立工作流状态，而是表格中是否存在负责人，以及该负责人对应的要求采集字段是否已填写。

## 决策

系统将 Excel/WPS 表格视为状态事实源。每个任务必须配置负责人列和采集列。系统每次同步表格后按行解析：

- 负责人列用于识别内部员工。
- 必填采集列全部非空时，该负责人状态为已提交。
- 必填采集列部分非空时，该负责人状态为部分填写。
- 必填采集列全部为空且未逾期时，该负责人状态为未开始。
- 超过截止时间且未提交时，该负责人状态为逾期。
- 负责人无法匹配内部员工时，进入匹配异常，不自动催办。

## 影响

好处：

- 不依赖额外表单工作流状态。
- 与当前 Excel 填报习惯一致。
- 后续接入 WPS API 时只替换表格获取方式，不改变状态判定模型。
- 可以同时展示填写内容和提交状态。

代价：

- 对表头、负责人列和采集列格式有要求。
- 如果负责人名称不唯一，需要引入工号、邮箱或手机号辅助匹配。
- 如果同一负责人多行反馈，需要额外定义聚合规则。

## 后续条件

上线前必须确定负责人唯一识别方式、重复负责人处理规则、必填列配置方式，以及表格格式变更后的异常处理流程。
