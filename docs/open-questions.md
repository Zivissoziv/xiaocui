# 待确认问题

## 业务边界

1. 催办对象主要是企业内部员工，还是也包含外部供应商、客户、合作伙伴？已确认：只包含内部员工。
2. 表单目前主要在哪里填写：Excel、企业微信、钉钉、飞书、OA、自研系统，还是混合存在？已确认：一期通过 Excel，后续通过内网 WPS API 下载表单。
3. 任务发起人是否需要看到填写内容，还是只需要看到提交状态？已确认：填写内容和状态都要看到。
4. 逾期后是否允许自动抄送直属主管或部门负责人？已调整：一期先不考虑升级策略和主管抄送。
5. 是否存在合法的延期、豁免、代填、退回补充流程？

## 技术集成

1. 是否有统一组织架构服务，例如 LDAP、AD、HR 系统或企业通讯录？
2. 是否有统一消息网关，还是要分别接企业微信、钉钉、飞书、邮件？
3. 现有表单系统是否提供查询提交状态的 API？已确认：提交状态可由负责人列和采集列填写情况判断；后续从 WPS API 获取表格文件。
4. 内网部署环境偏向 Java、Node.js、Python，还是已有统一技术栈？已确认：后端 Java + Spring Boot + Spring AI + MyBatis，数据库 MySQL，前端 Vue + Element。
5. 是否需要和统一认证、单点登录、权限中心打通？

## 新增待确认

1. 负责人列里的姓名是否唯一，还是需要员工工号、邮箱、手机号等辅助识别字段？
2. 一个人是否可能在同一个表格里出现多行？如果出现多行，是任意一行填写即算提交，还是每一行都要填写？
3. 采集列是所有列都必填，还是不同任务可以配置部分必填、部分选填？
4. 表格是否允许配合方直接修改负责人列或表头？
5. WPS API 下载表格时能否拿到文件版本号、更新时间或修改人？
6. 后续如果要做升级策略，主管关系来自哪里：表格列、组织架构接口、通讯录，还是需要先手工维护？
7. 催办渠道优先使用什么：邮件、企业微信、钉钉、飞书，还是已有内部消息中心？
