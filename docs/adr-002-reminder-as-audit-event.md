# ADR-002: 催办发送必须作为审计事件保存

## 状态

建议采纳

## 背景

催办不仅是消息发送，也是企业协作中的责任记录。后续经常需要回答：什么时候催过、催给谁、用了什么渠道、是否发送成功、为什么没有继续催。

## 决策

每一次催办动作都保存为 `ReminderEvent`，并保存当时的消息快照、触发规则、发送渠道、发送结果和失败原因。

## 影响

好处：

- 支持复盘和审计。
- 支持任务发起人判断是否需要人工介入。
- 避免模板修改后历史消息含义被改变。
- 支持统计不同催办策略的效果。

代价：

- 数据量会随任务规模增长。
- 需要定义日志保存周期和脱敏策略。

## 后续条件

在接入真实 IM 或邮件渠道前，需要确定消息日志保留期限、敏感字段脱敏规则和管理员查看权限。
